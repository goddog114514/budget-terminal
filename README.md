# BUDGET::TERM — 个人记账与自动理财规划终端

一个仿 PowerShell 风格的本地记账 Web 应用：黑色背景、等宽字体、绿/白/彩色文字，
用**命令行输入** + **顶部按钮（辅助）**双通道操作，所有数据保存在浏览器 `localStorage`
（无需安装、无需联网、无后端）。

**单文件应用：** 双击 `index.html` 用浏览器打开即可使用。

---

## 快速上手

打开后即可直接在底部命令行输入，例如：

```text
set budget 1000        # 设置本周期(默认自然月)固定预算 1000 元
add 50 餐饮 午餐        # 记一笔 50 元餐饮消费，备注“午餐”
amort 3600 365 房租 年付  # 分摊成本：3600 元按 365 天摊到每天(≈¥9.86/天)，投资只按总价记一次
add 300 购物 外套       # 再记一笔
list                    # 查看所有消费记录
budget                  # 看预算进度条与剩余额度
pay 1 all               # 把第 1 笔对应的投资标记为“已投资”
summary                 # 本周期自动总结
summary week            # 本周总结
export md               # 下载 Markdown 报告
```

每笔消费会自动换算"占用总花费"与应投金额并关联显示：

- **占用总花费 = 消费 ÷ N**，其中 **N = 消费占比**（默认 `0.85`，即消费占预算的 85%）
- **投资比例 = 1 − N**（默认 `15%`），其中 **13% → 货币基金、2% → 指数基金**（投资池内按 13:2 拆分）
- 例（默认 N=0.85）：消费 `¥850` → 占用 `¥1000`，应投 货币 `¥130` + 指数 `¥20`
- **比例可调**：`set invest 10`（投资 10%）/ `set consume 90`（消费占 90%）/ `set ratio 0.85`
- **剩余自动结转下一周期**；**透支自下一周期扣除**（见下"预算模型"）

例如 `add 50 餐饮 午餐`（默认比例）会算出：占用总花费 `¥58.82`，应投货币 `¥7.65` + 应投指数 `¥1.18`。
改成 `set invest 10` 后，同样 ¥50 变为占用 `¥55.56`，应投货币 `¥4.81` + 应投指数 `¥0.74`。

### 投资池与一键投资
- 每条记录拆为两栏 **应投货币** 与 **应投指数**，各自把"未投部分"跨期累加成池。
- 界面顶部「理财条」实时显示两池：**应投货币池 / 应投指数池**（未投累计）＋各自累计已投。
- 当**应投货币池累计 ≥ ¥100**、**应投指数池累计 ≥ ¥20** 时，该池金额**变绿**，旁边的 **`全额投资`** 按钮点亮（在此之前显示“待满 ¥100/¥20”并禁用）。
- 点 **`全额投资`**：把该种整个未投池一次性投入并清零，金额**按各笔未投金额比例自动分摊**（支持一笔只投一部分），记入累计已投，池归零重新累计下一批。
- 例：消费合计 ¥850 → 应投货币池 ¥130、应投指数池 ¥20，两个全额投资按钮同时点亮；点货币“全额投资”即投入整池 ¥130（清池），指数同理投 ¥20。
- `list` 每行右侧按钮可一键把该行应投货币+指数全部标记已投（再点重置），行内状态即时更新。

## 总结（summary）用法

### 1. 按类别筛选
在任意总结命令**末尾加上类别名**，即只统计该类别的消费；不加则统计全部：

```text
summary day            # 今日全部
summary day 餐饮        # 今日只看餐饮
summary week 医疗       # 本周只看医疗
summary month 餐饮      # 本自然月只看餐饮
summary month 2027-07 餐饮   # 指定月份 + 类别
summary 医疗            # 省略窗口关键字 → 当前记账周期 + 医疗
summary cat 交通        # 当前周期各类别占比(限定交通)
```

- 类别名会显示在标题里，如 `═ 今日 2027-08-18  [类别: 餐饮] 总结 ═`。
- 窗口内没有该类别时会给出提示，并列出**现有类别**（含自定义类别）。
- 类别支持 Tab 补全（已知类别 + 历史记录里出现过的所有类别）。

### 2. 平均每日消费
除 `summary day` 外，每次总结末尾都会多出一段：

```text
 ── 平均每日消费 ──
 日均 ¥16.67   = 窗口总消费 ¥300.00 ÷ 18 天
 统计口径: 窗口 30 天, 已过 18 天
```

- 计算方式：**窗口总消费 ÷ 统计天数**（已按类别筛选时，就是该类别的日均）。
- **进行中的窗口**只按“已过天数”平均（如本月 18 号看月总结 → ÷18 天），避免被未到的日期稀释；
  **已结束的窗口**（如 `summary month 2027-07`）按整个窗口天数平均。
- `summary day` 不计算（单日总量即日均，无意义）。
- 预算行（本期发放 / 占用 / 结转 / 累计余额）仍是**当前记账周期**口径，不随窗口或类别变化。

## 消费列表 list

`list` 现在可以按 **类别** 和 **日期/月份** 组合筛选：

```text
list                      # 全部记录
list 餐饮                  # 只看类别
list @2027-08-18          # 只看某一天
list @2027-08             # 只看某个月(整月)
list @today               # 今天
list @period              # 当前记账周期(可跨月)
list @month               # 本自然月
list 餐饮 @today           # 类别 + 日期 组合
list 交通 @2027-07         # 类别 + 月份 组合
list 餐饮 20               # 类别 + 最近 20 条
```

- 标题会显示本次筛选条件与**合计金额**，例如 `消费记录 (3 条)  [筛选: 类别=餐饮  日期=2027-08-18]`。
- 无匹配时会提示并列出**现有类别**，方便改条件。
- `@` 后面也接受中文关键字：`@今日`、`@周期`、`@本月`。

### 顶部「消费列表 ▾」下拉
工具栏的**消费列表**按钮带下拉菜单，鼠标即可选 4 种范围：

| 选项 | 等价命令 |
| --- | --- |
| 当日 | `list @today` |
| 周期 | `list @period` |
| 月份 | `list @month` |
| 手动输日期… | 弹窗填**日期**和/或**月份**（+可选类别），如 `list 餐饮 @2027-07-15` |

#### 「手动输日期…」弹窗：日期/月份统一格式
弹窗里的两个输入框**统一用 ISO 写法**，与命令 `@日期` 完全一致，不再是本地化的 `2027/8/5`、`2027年8月`：

| 输入框 | 统一格式 | 等价命令 |
| --- | --- | --- |
| 日期 | `YYYY-MM-DD`（如 `2027-08-18`） | `list @2027-08-18` → 只看当天 |
| 或 月份 | `YYYY-MM`（如 `2027-08`） | `list @2027-08` → 看整月 |

- **宽容输入、自动归一化**：`2027/8/5`、`2027.8.5`、`20270805`、`2027年8月5日`、全角数字/破折号等
  都会在**失焦时**自动改写为 `2027-08-05`；月份同理（`2027.8` → `2027-08`）。
- **实时校验**：非法输入（如 `2027-13`、`2027-02-30`）会在提示行用**黄色**说明原因，并阻止提交；
  `2027-02-30` 会明确提示该月只有 28 天。
- **执行预览**：弹窗底部实时显示将要执行的命令（统一格式），如 `将执行:  list 餐饮 @2027-08-05`，
  填日期显示绿色、只填月份显示青色。
- **保留鼠标选择**：输入框右侧的 **📅** 仍可弹出系统日历/月份选择器，选完同样回填成统一格式
  （不支持弹出选择器的浏览器会提示改为手动输入）。
- 只填月份 → 看整月；两个都填 → 优先日期。

## 分摊成本 amort

有些花费是**一次性付掉、但要用很久**的：年付房租、年费会员、保险费、域名/服务器续费、大件耐用品。
它们不该把一整年的钱压在某一天，也不该被当成"当天的消费"。

`amort` 就是为这类花费准备的：**输入总价 + 分摊天数，把花费平均摊到每天**，而**投资只按总价记一次**。

```text
amort 3000 365 房租 年付房租     # 总价 3000 元，摊到 365 天 → 每天 ≈¥8.22
amort 600 12月 会员 年费         # 天数也可写 12月 / 12m（按 30 天/月折算 = 360 天）
amort 1200 90 保险 @2027-08-01   # 指定开始日期（@ 位置随意，与 add 一致）
```

| 参数 | 说明 |
| --- | --- |
| `<总价>` | 一次性付出的总金额（> 0） |
| `<天数>` | 分摊天数，**2 ~ 3650**；可写 `12月` / `12m` / `12个月` → ×30 天 |
| `<类别>` | 与 `add` 同一个类别体系（自定义类别、Tab 补全、配色都照旧） |
| `[备注..]` | 可选，含空格请加引号 |
| `[@开始日期]` | 可选，默认今天；日期位置随意（`@` 参数不占位置） |

### 两个口径（重点）

设总价 **T**、分摊天数 **N天**、消费占比 **N%**（默认 85%）：

| 口径 | 算法 | 说明 |
| --- | --- | --- |
| **消费（计入每一天）** | `每天 = T ÷ N天`，**在生效窗口的每一天各计一次** | 记录里的金额就是**每天**的量；周期占用、`budget`、`summary`、燃尽预测、日均、消费列表都按"落在统计窗口内的天数"自动累计 |
| **投资（只记一次）** | `应投 = T ÷ 消费占比`，再按 **13:2** 拆货币/指数 | **不分摊**：整笔总价的应投额一次性计入投资池（池本来就是跨期累计的总数） |

- **生效窗口**：从**起始日期**（命令行 `@开始日期`，弹窗里的「起始日期」精确到 **日**，留空 = 今天）
  起连续 `分摊天数` 天。这笔钱在这段区间内**每天**都算一份消费；区间之外（记之前 / 摊完之后）一分都不算。
- 关键恒等式：**当统计窗口完整覆盖生效窗口时**，`Σ(每天 ÷ 消费占比) = 总价 ÷ 消费占比` ——
  所以"按天摊"与"按总额算"得到的**投资总数完全相等**，只是投资记录的是**总数**、不跟着每天重复计算。
- 例：`amort 3000 365 房租`（默认比例）→ 每天消费 `¥8.22`、每天占用 `¥9.67`；
  应投货币 `¥458.82` + 应投指数 `¥70.59`（= 3000 ÷ 0.85 × 15%，**一次记入**）。
- **只看部分窗口就只算对应的天数**：8 月 30 日记的年付房租，8 月的周期消费 = 2 天（8/30、8/31）；
  9 月的周期消费 = 30 天；把一整年 365 天都覆盖进去时 = 每天 × 365。
- 改投资比例（`set invest`）时，分摊成本与普通记录一样**按总价重算**应投额。

### 在列表 / 报告里长什么样

```text
#3  2027-08-30  房租  ¥8.22  [分摊365天: 总3000.00 → 每天8.22  2027-08-30~2028-08-28]  应投货币 ¥458.82  应投指数 ¥70.59
```

- 列表行里的金额是**每天**的消费额（与周期占用同一口径），方括号里标出**总价 / 天数 / 生效区间**，避免看不出处。
- **日期筛选按"窗口有交集"命中**：`list @2027-09-15` 能列出这笔分摊（它在 9-15 那天确实在摊），
  `list @2027-08-29`（生效前一天）则列不到。
- `list` 的合计按**落在筛选窗口内的天数**计：`list @2027-08-31` 合计 `¥8.22`（当天那一份），
  `list @2027-09` 合计 `¥8.22 × 30 = ¥246.60`（整月那 30 天）。标题下方会显示"其中分摊成本 ¥X"。
- `summary` 的总额/类别占比/日均、`export` 报告都按同一口径统计，无需额外操作；
  总结里会多一行 **`其中分摊成本`**（它是"窗口总消费"里的一部分，不是额外再加）。
- `summary` 的**今日**窗口只算当天那一份；`list @today`、右上角「今日预算」圆点同理。
- 导出的逐笔记录会额外标注 `分摊365天(2027-08-30~2028-08-28 总价¥3000.00 → 每天¥8.22)`。
- `del` / `update` 的提示里也会带上"分摊 N 天 · 总价 ¥X"。
- `update <id> <金额> <类别>` 对分摊记录把 `<金额>` 解释为**每天**的金额，总价按 `每天 × 天数` 同步重算。
- **累计可用余额（含结转）只累计到今天为止**已发生的天数 —— 记一笔年付房租不会让余额立刻变负，
  未来的那些天要等日历走到才逐日计入。

### 「记一笔」弹窗改成两个选项卡

工具栏 **`+ 记一笔`** 打开的弹窗，现在顶部有两个选项卡：

| 选项卡 | 用途 | 字段 |
| --- | --- | --- |
| **单笔消费**（默认） | 原来的一笔消费 | 金额 / 类别 / 日期 / 备注 |
| **分摊成本** | 总价摊到每天 | **总价** / **分摊天数** / 类别 / **起始日期（精确到日，留空 = 今天）** / 备注 |

- 分摊选项卡里有**实时预览**：`= 每天 ¥8.22 × 365 天（合计 ¥3000.00），从 2027-08-17 起` +
  `生效区间: 2027-08-17 ~ 2028-08-16（含首尾，共 365 天）` +
  `应投按总价一次记入: 货币 ¥458.82 + 指数 ¥70.59`；
  填错（天数越界、每天不足 ¥0.01、**日期非法**）会用**黄色**说明原因并阻止提交。

## 每日可用余额 与 红黄绿圆点

### 手动设置每日可用余额
在工具栏 **「配置预算」** 弹窗的下半部分（或命令 `set daily <金额>`）手动设置**每日可用余额**：

```text
set daily 100       # 每天可用 100 元
set daily off       # 取消设置
```

它用来判断**今天花了多少 / 每天可用多少**，与周期预算互不影响。

### 右上角红黄绿"实心圆点"
状态栏右上角用两个**实心圆点**同时显示「今日预算」和「周期预算」，格式为
**标签 + 圆点 + 数值**：

```text
今日预算：●剩余55%    周期预算：●已超额114%
```

| 圆点颜色 | 触发条件（阈值同 `set alert`，默认 80%/100%） | 圆点后文案 |
| --- | --- | --- |
| 🟢 绿 | 已用 < 80% | `剩余 X%`（X = 100 − 已用%） |
| 🟡 黄 | 80% ≤ 已用 < 100% | `接近上限 X%` |
| 🔴 红 | 已用 ≥ 100% | `已超额 X%` |
| ⚪ 灰 | 未设置每日额度 | `未设置额度` |

- **今日预算** = 今日消费 ÷ 每日可用余额（未设置每日额度时显示灰点）。
- **周期预算** = 本期占用 ÷ 本期预算（与 `budget` 的进度口径一致）。
- 圆点是静态颜色，`budget` 命令末尾也会打印同样的两行圆点。
- 阈值仍沿用 `set alert <p1,p2,…>`：圆点取**最低阈值**作为黄灯起点、**最高阈值**作为红灯起点
  （默认 `80,100`；写成 `set alert 90,100` 则 90% 才转黄）。圆点只有绿/黄/红/灰四态。

## 两种记账周期

1. **固定天数滚动周期**（适合“每两周/每 15 天”结算预算）
   ```text
   set period 15            # 从现在起，每 15 天滚动一期
   set periodstart 2027-08-04   # (可选)指定从哪天起算，之后每 15 天滚动
   ```
   预算、进度、超额预警、`summary` 均按当期 15 天窗口计算；超过第 15 天自动进入下一期。

2. **按月周期**（自然月或自定义起始日）
   ```text
   set period natural       # 回到自然月
   set monthstart 15        # 每月 15 日 ~ 下月 14 日为一期（想错位对齐时推荐）
   ```

## 预算模型（N% 消费 / (1−N)% 投资 + 结转）

设某期发放总预算 **B = 1000**，**N = 消费占比**（默认 `0.85`，可调）：

- 消费占总花费的 **N%**；每笔消费 `E` 记为本期**占用** `E ÷ N`。
  默认 N=0.85：消费 850 → 占用 1000；消费 425 → 占用 500。
- 投资的 **(1−N)%** 作为自动理财，货币/指数按 **13:2** 拆池：
  默认下即 **13% → 货币基金、2% → 指数基金**（占占用额）。
  例：消费 850 → 应投货币 130 + 指数 20（合计 150）。
- **结转/透支（跨期累计）**：
  - 本期占用 < 发放 → 差额为"剩余"，**自动结转到下期**（可用余额增加）。
  - 本期占用 > 发放 → 差额为"透支"，**自下一期发放中扣除**。
  - 例：消费 425、占用 500 → 本期可结转 500，可用余额 500；下期发放时余额 += 1000。
  - 例：消费 900、占用 1058.82 → 透支 58.82，可用余额为 -58.82，下期 +1000 后先扣回。

### 可调投资比例
比例由系数 **N** 控制，`(1−N)` 即投资比率：

| 命令 | 效果 |
| --- | --- |
| `set invest 15` | 投资 15% → 消费占比 N=0.85（**默认**）；货币 13% + 指数 2% |
| `set invest 10` | 投资 10% → N=0.90；货币 8.67% + 指数 1.33% |
| `set consume 80` | 消费占比 N=0.80 → 投资 20%；货币 17.33% + 指数 2.67% |
| `set ratio 0.85` | 用小数直接设 N（等价 `set consume 85`） |

- 允许范围：消费占比 **50%~100%**（即投资比例 0%~50%），越界会被拒绝。
- 投资池内部**始终按原始 13:2 比例拆分**，只是随 `(1−N)` 整体缩放。
- **改比例会按新口径重算全部历史记录的应投额**（已投金额不会超过新的应投额），
  所以 `budget` / `summary` / `export` / 理财条都会同步更新。
- 当前比例可随时用 `config` 查看。

顶部状态栏、`budget`、`summary`、`export` 均按此口径显示「本期消费 / 应投 /
已占用 / 可结转·透支 / 累计可用余额」，并据占用率触发预警（默认 80%/100%）。

> **总结窗口 vs 预算口径**：`summary` 的**消费窗口**可选 —— 无参数 = 当前记账周期；
> `summary month` = **自然月（1 日~月末）**，与记账周期解耦（即使周期设成 15 天滚动，
> 也能看日历月账单）；`summary day/week` 对应今日/本周。
> 但表中的**预算行**（本期发放 / 本期占用 / 结余·透支 / 累计余额）始终按**当前记账周期**计算，
> 因为预算本来就是按周期发放与结转的。

## 本地备份与防丢失

数据默认存在浏览器 `localStorage`，刷新/换浏览器/清理缓存会丢失。三种本地保存方式（工具栏按钮）：

1. **存到本地目录（推荐，防自动丢失）** — 只需选一次文件夹：
   - 程序把全部记录/设置写入该目录的 `budget_term_backup.json`，之后**每次改动都自动写盘**；
   - 所选目录会记在 IndexedDB，**以后每次点开应用**：若浏览器仍授权，打开即自动重连并继续自动写盘；若新会话授权过期，在你第一次点击/按键时**自动**重新申请授权（无需再专门点按钮）；
   - 需要 **Chrome / Edge / Opera**（File System Access API，建议用 `http(s)` 或本地服务器方式打开，持久授权更稳定）。
2. **备份 .json** — 任何浏览器可用：下载一份完整快照文件，可存到本地归档。
3. **导入 .json…** — 选之前备份的文件即可整体恢复记录与设置（会替换当前数据）。

提示：以上文件都是**纯文本 JSON**，可放心存到云盘/网盘；即使浏览器数据全清，导入一次即可找回所有记录。

## 说明 / 提示

- 未开启“存到本地目录”时，数据只存当前浏览器；请勿用隐私/无痕模式，或用「存到本地目录 / 备份 .json」留存。
- 修改 `预算金额` 会影响"发放进度"与结转；已录消费不受影响（但其应投金额始终按新口径换算）。
- 修改**投资比例**（`set invest` / `set consume`）会**重算所有历史记录的应投额**；
  已投金额按新应投额封顶，不会被改大。可用 `config` 随时查看当前比例。
- 导出报告（`export md/txt`）为另存的报告文件，与上述 JSON 备份不同。
- **分摊成本（`amort`）**：每天计消费、投资按总价一次记入；`list` 行的金额是**每天**口径，
  方括号里标着 `[分摊N天: 总X → 每天Y  起~止]`。两者口径说明见上文「分摊成本 amort」。

### v0.0.7
**修复 v0.0.6 遗留的恶性缺陷：分摊成本只在"记账那一天"被算一次。**
`amort` 记录的 `amount` 是**每天**的金额，但所有统计都按 `r.date` 单日筛选/求和 ——
于是那笔钱除记账当天外，在**每日预算、周期预算、消费列表、以及各种总结（day/week/month/cat/导出）**
里全部查不到、也不计入消费。**数据结构与备份格式一个字都没改**（`amount` 仍是每天口径），
改的只是"按天窗口统计"的口径。

- **现象**：`amort 3000 365 房租`（8 月 30 日记）之后 ——
  ① 8 月 31 日右上角「今日预算」当天消费 = `¥0.00`（只有 8/30 显示 `¥8.22`）；
  ② 8 月整月的周期消费只有 `¥8.22`（应为 8/30、8/31 共 2 天 = `¥16.44`）；
  ③ `list @2027-08-31` 返回"暂无匹配记录"，9 月的 `list @2027-09` 同样列不到这笔；
  ④ `summary` / `summary day` / `summary month` / `export` 的总消费都只算一天，
     `summary month` 的"日均"于是被除成 `¥0.27`（应为 `¥0.55`）。
- **原因**：`periodSnapshot()` / `todaySnapshot()` / `totalCharge()` / `collectWindow()` /
  `doList()` 五处各自写了一遍 `filter(r => r.date 在区间内).reduce(s + r.amount)` ——
  "记一天"被当成了记录的全部生命周期。v0.0.6 只把**消费口径**做成"每天金额"，却没做"窗口内的天数"。
- **解决**：新增**窗口统计的唯一入口**并让上面五处全部复用（失败模式 F12/F13：一个数字两套口径）：
  - `recWindow(r)` = 生效窗口（`date` 起连续 `recDays(r)` 天，闭区间；普通消费即 `date~date`，旧记录零特判）；
  - `recDaysInRange(r,start,end)` = 窗口与统计区间的**交集天数**；
  - `recInWindow(r,start,end)` = 行筛选统一口径（**有交集就算**，不再只认 `r.date`）；
  - `recAmountInRange(r,start,end)` = 该记录在区间内的消费额 = `交集天数 × 每天金额`；
  - `recAmountUpToToday(r)` = 只累计到今天（`totalCharge` / 累计可用余额用，未来的天数不提前占用）；
  - `sumRange(rows,start,end)` / `collectWindow(start,end,cat)` = 合计与"其中分摊"小计（`periodSnapshot` 也改为复用 `collectWindow`）。
- **修好之后**：分摊成本在生效窗口内的**每一天**都计入消费 —— 每日预算、周期预算（按落在本期内的天数）、
  消费列表（日期/月份/周期筛选都按窗口交集命中）、总结与导出全部一致；

### v0.0.6
新增**分摊成本**：一次性付掉的总价可以按天数摊到每天，而**投资只按总价记一次**（不分摊）。
数据格式**向后兼容** —— 旧备份照常导入，普通记录的字段与口径一个字都没变。

- **新增命令 `amort <总价> <天数> <类别> [备注..] [@开始日期]`**（别名 `amortize`）
  - 需求：有些花费一次性付掉却要用很久（年付房租、年费会员、保险、续费），不该全压在一天，
    也不该被当成"当天消费"；而"相关的投资只记录总数，不分摊"。
  - 解决：记录里 `amount` 存**每天**的金额（`总价 ÷ 天数`），新增 `amortDays`（分摊天数）
    与 `amortTotal`（当初的总价）；**应投额一律按 `amortTotal` 算并只记在该笔记录上**。
  - 为什么这样切：所有"消费口径"的派生（周期占用 / `budget` / `summary` / 燃尽 / 日均）与旧记录
    **完全同义**，不需要任何特判；而投资侧满足恒等式
    `Σ(每天 ÷ 消费占比) = 总价 ÷ 消费占比`，即"按天摊"与"按总额算"的**投资总数完全相等**，
    所以"投资只记总数"不会让投资池少算。
  - 天数支持 `12月` / `12m` / `12个月`（按 **30 天/月** 折算，口径可预期、不随日历漂移），

    也可与类别组合，如 `list 餐饮 @today`；标题会显示筛选条件与合计金额。
  - 无匹配时提示并列出**现有类别**；`@` 后同时支持中文关键字 `@今日/@周期/@本月`。
- **工具栏「消费列表 ▾」下拉菜单**：4 个快捷范围 **当日 / 周期 / 月份 / 手动输日期…**，
  最后一项弹出窗口可填日期和/或月份（+可选类别）。
- **新增「每日可用余额」手动设置**：命令 `set daily <金额>` / `set daily off`，
  也可在**「配置预算」**弹窗下半部分设置（含红黄绿圆点实时预览）。
- **右上角状态改为红黄绿「实心圆点」且不闪烁**：
  `今日预算：●剩余55%    周期预算：●已超额114%`
  - 圆点前**不放文字**（颜色由圆点本身表示），只保留「今日预算／周期预算」标签 + 圆点 + 数值。
  - 绿 `<80%` 显示"剩余X%"；黄 `80%~100%` 显示"接近上限X%"；红 `≥100%` 显示"已超额X%"；
    未设置每日额度时为灰点"未设置额度"。规则仍由 `set alert` 阈值控制。
  - 删除了原「已超额 ⚠」的闪烁动画；`budget` 命令末尾也会打印同样的两行圆点。
- `config` 增加「每日可用余额」显示；`set`/`list` 的 Tab 补全同步补充新参数。
- **修复：新增弹窗按钮文字为黑色、在近黑背景上看不清**
  - 现象：「配置预算」弹窗下半部分的 **`保存每日额度`**，以及「手动输日期…」弹窗的 **`查看` / `取消`**，
    文字是浏览器默认的黑色（`ButtonText`），落在 `#07090a` 的弹窗底色上几乎看不见。
  - 原因：这三个新按钮只被 `.mbtns button` 设了边框/内边距，**没有设 `color`**，于是回落到浏览器默认黑色；
    而同弹窗里的旧按钮（`取消`/`应用于当期`/`设为默认`）各自有 id 级颜色规则，所以只有新按钮出问题。
  - 解决：`.mbtns button` 增加**兜底颜色 `var(--green)`**（以后新增弹窗按钮不会再变黑），
    并为 `#b_daily_save`/`#d_ok`（绿）、`#d_cancel`（红）、`#b_daily_off`（灰）补上颜色与 hover 规则；
    同时给 `:root` 加 `color-scheme:dark`，让日期/月份输入框的原生日历图标、数字微调箭头也按暗色渲染。
- **「手动输日期…」弹窗的日期/月份改为统一格式**
  - 现象：同一个弹窗里，日期框显示本地化 `2027/8/5`、月份框显示 `2027年8月`，两者不一致，
    也和命令 `@2027-08-18` / `@2027-08` 以及 `list` 标题里的 `日期=2027-08-18` 对不上。
  - 解决：两个框统一为 **ISO 文本输入**（日期 `YYYY-MM-DD`、月份 `YYYY-MM`），
    宽容接受 `2027/8/5`、`2027.8.5`、`20270805`、`2027年8月5日`、全角字符等写法，**失焦即归一化**回填；
    新增**实时校验**（非法日期/月份黄色提示并阻止提交）与**执行预览**行 `将执行:  list 餐饮 @2027-08-05`；
    原型选择器保留为输入框右侧 **📅** 按钮（`showPicker()`，选完回填统一格式）。
  - 相关函数：`normDateText()`（归一化）、`updateDatePreview()`（校验+预览）、`openNativePicker()`（📅）。

### v0.0.2
- **修复：「应投」显示为 `¥0.00` 的记录无法标记已投资**
  - 现象：某笔应投货币/指数实际金额小于半分（如 `¥0.03` 的消费 → 应投货币 `¥0.0046`、指数 `¥0.0007`），
    点「标记已投资」后状态立刻变回「未投资」，反复点也没用。
  - 原因：应投额按 **2 位小数**四舍五入成 `0.00` 后存起来，而判定逻辑要求 `应投 > 0` 才算"可投"，
    于是永远判为"未投足"；同时「全额投资」按"分"为单位分摊，小于 1 分的零头直接被跳过，池子也清不掉。
  - 解决：**投资金额内部统一改为 6 位小数精度**（`r6`），UI 仍只用 `money()` 显示 2 位；
    判定改用极小浮点容差 `INV_EPS`；「全额投资」分摊单位由"分"提升到 `1e-6` 元（`INV_UNIT`），零头也能投掉。
  - 效果：上例现在可以正常标记为「已投资」，再次点击可切回「未投资」；旧数据在加载时自动按新精度重算，
    原本已标记"已投足"的记录会吸附到新应投额，不会因精度变化退回「部分/未投」。
- 新增「**无需投资**」状态：应投恒为 `0.00` 的记录状态显示「无需」，按钮置灰，`pay` 命令会提示无需投资。
