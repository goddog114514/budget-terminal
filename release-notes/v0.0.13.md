## 一、做了什么

| 能力 | 说明 |
| --- | --- |
| 关键词 | `search 餐饮` 命中「类别」「备注」「地点」任一字段，大小写不敏感；`search 午餐 餐饮` 多个关键词 **AND** |
| 编号 | `search #12` 精确命中记录 id；纯数字 `12` 也同时按编号匹配（金额对不上也能找到 `#12`） |
| 金额 | `search 50`（等值）、`search >100` / `>=100` / `<50` / `<=50`（比较）、`search 100-200`（区间，写反自动纠正） |
| 日期 | `search @2027-08-18` / `@2027-08` / `@today` / `@period` / `@month`；也接受 `今天` / `本月` / `周期` 与不带 `@` 的 ISO 写法 |
| 组合 | 条件之间用空格分隔、**同时满足**：`search 餐饮 @2027-08`、`search >100 @2027-08` |
| 结果 | 与消费列表同构的 `▓ 查找结果`：条数 + 条件、合计、每行 `[标记已投资]` 与 `✎ 编辑` 原样可用；命中关键词加底色 |
| UI | 工具栏最右侧**只有一个搜索框**：`Enter` 执行（回灌 `search …`）、`Esc` 清空；解析/匹配/渲染与命令行同一套 |

## 二、使用示例

```text
search 餐饮                  # 类别 / 备注 / 地点 任一处含「餐饮」
search 午餐 餐饮              # 两个词都命中才算(AND)
search #12                   # 按编号
search 3000                  # 金额 = 3000(分摊记录的总价也算)
search >100                  # 金额大于 100
search 100-200               # 金额区间
search @2027-08              # 2027 年 8 月
search 餐饮 @2027-08          # 8 月的餐饮
```

## 三、口径与边界（重要）

1. **金额双口径**
   - **等值**（`50`）：认「每天金额」**或**「总价」——用户可能照抄行里的 `¥8.22`，也可能记得「年付 3000」。
   - **比较 / 区间**（`>100`、`100-200`）：**只按总价**。否则年付房租会因为"每天 8 元"混进 `<=50` 的小额筛选，
     明显反直觉。这条由变异组 `m_search_amort_total` 守着。
2. **日期窗口与 `list` 完全一致**：分摊成本只要**生效窗口与查询窗口有交集**就算命中，
   查 `@2027-09-01` 能找到 8 月 30 日记的 365 天房租。合计也复用 `sumRange()`，只算落在窗口内的天数。
3. **条件不做模糊猜测**：
   - 无法识别的 `@…`、`#abc` → 黄色提示可用写法，不会静默退化成"返回全部"。
   - 日期/月份/区间只取**第一个**，重复时给提示；金额条件则全部生效。
   - 无匹配 → 提示并列出**现有类别**，方便改条件。
4. **只读**：查找不写账本、不落盘、不压撤销栈；结果行里的按钮仍走既有提交点（H4）。

## 六、修复 · `report` 的预算行按查询的那一段合计（同版，用户反馈）

**现象**：`report @2026-09` 标题写着 2026-09，表里的「本期发放(基准)」却是今天这一期的预算（用户截图），
「本期消费 / 结余·透支 / 累计可用余额 / 发放进度」同样错位 —— 窗口统计是 9 月，预算行是 11 月。

**根因**：`printSummaryReport()` 里写死 `periodSnapshot()`（= `currentPeriod()`），
`chartBuckets()` 的日均发放参考线也一样；窗口参数只影响消费统计，不影响预算口径。

**用户口径**：一个**月份**可能跨两个记账周期 —— 发放基准与消费都应变成**这两期之和**；
第一期仍按「窗口起点所在周期」算，第二期接着第一期往后推。

**修法**（一处实现，不留第二套）：

| 点 | 做法 |
| --- | --- |
| 区间来源 | 新增 `budgetPeriodsOfWindow(win)`：首期 = `periodOfWindow(win)`，之后用 `nextPeriodStart` 逐期往后推，直到盖住窗口终点 |
| 快照 | 新增 `budgetOfWindow(win)`：`B` = 各期发放之和，`consumption` = 首期起点~末期终点整段，`days` = 区间天数；`summary` / `report` / `chart` 共用 |
| 历史余额 | `availableBalance(p)` 支持带 `lastStart` 的多期区间：发放累计到最后一期、占用累计到区间末（不预支未来）；单期/无参时与 v0.0.12 完全一致 |
| 两个新助手 | `grantedTotalAt(startStr)` / `totalChargeAt(dayStr)`（原 `grantedTotal()` / `totalCharge()` 变成省略参数的特例） |
| 图表同口径 | `chartBuckets(win, isDay, cat)`：日均 = 各期发放合计 ÷ 区间天数，柱状图虚线 / 参考发放额度 / 预算使用率同源 |
| 可见性 | 区间与窗口不一致时，预算总结表头多一行 `预算行口径: 2 个记账周期合计 2027-06-05 ~ 2027-08-04(发放/消费/结转均按该区间)`；完全重合时不打印 |

**行为变化**（月起日=5，默认预算 1000，9 月单独覆盖 1823.99 的示例）：

- `report @2026-09`（窗口 09-01~09-30，覆盖 08-05~09-04 与 09-05~10-04 两期）：
  本期发放 = 2600 + 1823.99 = **¥4423.99**，本期消费 = 两期整段之和 **¥5533.92**，结余/余额按该区间末快照；
  窗口总消费仍是 9 月自己的 ¥5043.92。
- 自然月周期（月起日=1）看自然月：区间 = 窗口，`N=1`，数字与修复前一致。
- `budget` / 顶栏 / `export` / `forecast` 仍是当前周期口径；金额口径、数据结构、存储、精度**一字未改**。
