## ⚠️ 升级后一个数字会变（属修正，不是数据损坏）

如果你的账本**改过记账周期**（`set period` / `set periodstart` / `set monthstart`）**并且**用
`budget set`（或「配置预算」弹窗「应用于当期」）设过当期预算，那么升级后
**「累计可用余额(含结转)」会变大**——因为之前那笔当期预算根本没被算进累计发放里。

例（示意数字，非任何真实账目）：`累计可用余额 ¥-2000.00` → **`¥-1100.00`**，
差额正是被漏算的当期预算 ¥900.00；**记录与「已投」金额分文未动**（已投货币/指数前后完全一致）。

## 修复清单

### 一、周期与预算结转账本

- **改过周期规则后，「当期预算」不计入「累计可用余额」**
  - 现象：`set period 15` / `set periodstart …` / `set monthstart …` 之后，`budget set 1200`
    只在「本期发放」显示，顶栏与 `budget` 的「累计可用余额」仍按默认预算累计。
  - 原因：账本起点 `settings.epoch` 只在加载时设定，之后改周期长度/锚点/月起始日不会更新它；
    而 `periodStartsUpTo()` 从这个旧起点**按当前规则 +N 天**推发放周期，
    推出的"周期起点"已不是真实周期边界，`periodBudget[真实起点]` 这个覆盖键永远匹配不上。
    另外滚动周期在"锚点之前"的日期上会把锚点钳到查询日期（`if(dateStr<A) A=dateStr`），网格进一步漂移。
  - 解决：`ensureEpoch()` 把起点吸附到"包含它的那一期的起点"；`periodBounds()` 允许负期数索引
    （锚点之前也落在同一条 `锚点 + n×L` 网格上）；改周期设置时先 `ensureEpoch()` 再保存。
- **周期最后一天仍显示"每天可花 …/天"**
  - 解决：剩余 0 天时改为「本周期已到最后一天, 还可消费 ¥X」，`forecast` 表格同步。
- **`forecast` 的「本期消费额度(85%)」标题写死 85%**
  - 解决：改为跟随实际比例（`set consume 80` 时显示 80%）。

### 二、备份与数据导入

- **导入 `.json` 与直接读 `localStorage` 结果不一致（旧版"已投"状态会丢）**
  - 现象：v0.0.1 / v0.0.2 备份（记录里是 `mmPaid` / `idxPaid` 布尔字段）用「导入 .json…」恢复后，
    原本「已投」的记录变回「未投」；同一文件放进 `localStorage` 再打开却正常。
  - 解决：抽出 `normalizeRecords()` / `normalizeSettings()`，**加载与导入共用同一套归一化**。
- **导入备份残留上一份数据的设置**：备份里没写的项（如 `dailyBudget`、`monthStart`）会保留导入前的旧值。
  → 设置改为**整体替换**，缺失项回落默认值（与"会替换当前数据"的说明一致）。
- **重复 `#编号`**：备份里的 `seq` 小于记录最大 id 时，导入后新增记录会撞上已存在编号，
  导致 `del` / `update` / `pay` 命中错误记录。
  → `seq = max(备份 seq, 记录最大 id)`，记录 id 缺失/重复时自动顺延。
- **损坏或手改过的备份会让应用报错**：`thresholds: null` 会抛 `state.settings.thresholds is not iterable`，
  导入中断且状态半新半旧。
  → `normalizeSettings()` 逐字段校验类型与范围（非法回落默认值）；`normalizeRecords()`
  修复可修复的记录（类别空 → "其他"、`2027/8/5` 之类宽松日期归一化），
  不可修复的（金额/日期不可用）跳过并在日志里提示跳过条数。

### 三、投资比例与投资池

- **`set invest 50` / `set consume 50` / `set consume 100` 被拒**
  - 现象：文档写的区间是"消费占比 50%~100%（投资 0%~50%）"，但端点值全被拒，`set invest 0` 也不行。
  - 原因：校验用了开区间 `newConsume>0.5 && newConsume<1`，且 `consumeShare()` 只认 `v<1`，
    即使放行 100% 也会被静默回落成默认 85%。
  - 解决：改为闭区间 `>=0.5 && <=1`；`consumeShare()` 允许 `N=1`
    （此时应投为 0，记录状态显示「无需投资」，投资池为空）。

### 四、交互与显示

- **`undo` / `redo` / `del` 之后，旧列表行的按钮会"假成功"**
  - 现象：撤销后终端里仍留着撤销前的记录行，点它的「标记已投资」会打印成功，其实记录早已不在 state 里。
  - 解决：行按钮先检查是否仍指向 state 中的同一条记录，失效行显示「已失效」并提示重新 `list`。
- **备注里的引号被吃掉**：`add 12.3 学习 说 "引号" 测试` 之类会被 `/"[^"]*"/` 正则切断成 `说 \`、`A\`。
  - 解决：`tokenize()` 改为按字符扫描（引号内支持 `\"` / `\\`），`quote()` 同步转义，弹窗提交的备注可原样往返。
  - 注意：**引号外**的反斜杠保持字面量，Windows 路径备注（`C:\temp\a`）不受影响。
- **`list @写错的日期` 静默列出全部** → 现在给黄色提示，并列出可用写法
  （`@YYYY-MM-DD` / `@YYYY-MM` / `@today` / `@period` / `@month`）。
- **`summary 2027-07` 忽略月份、按当前周期统计** → 现在按该**自然月**统计（等价 `summary month 2027-07`）。
- **改设置后顶栏不刷新**（`set budget` / `set alert` / `set period` / `set monthstart` / `set periodstart` / `set weekstart`）
  → 改完立即 `refreshHeader()`。
- **「配置预算」弹窗的每日额度提示不是实时的** → 输入框加 `input` 监听，
  按**输入框里当前的值**预览每日额度与红黄绿圆点（即文档承诺的"实时预览"）。

### 五、持久化与健壮性

- **写盘期间的改动会被丢掉**：开启「存到本地目录」后，一次写盘还没结束时发生的改动会被
  `fileWritePending` 直接跳过 → 增加 `fileWriteDirty` 标记，写完后补写一次。
- **受限环境下打开页面白屏**：`localStorage.setItem` 抛错（隐私模式、禁用存储、某些打开方式）时
  `save()` 未捕获，boot 中断 → 现在捕获并只提示一次「本次数据仅存在于内存中，请用 [备份 .json] 保存」。
- **启动时的数据自检**：`loadState()` 遇到金额/日期损坏的记录会跳过，并在启动日志说明条数。
- **死代码清理**：`investAmount()` 里重复的第二次分摊循环、`validateCategory()` 里的空 `forEach`。

## 已知限制（本次未改动，属模型固有）

- 改周期长度会按新规则**重新解释历史发放期数**，因此「累计可用余额」会随周期规则变化（结转模型使然）。
- 记录 `@未来日期` 的消费会立刻计入「累计可用余额」（当期视图仍只统计当期）。
