## 一、合并内容

### 1. H5（来自 v0.09-rev.1）：双通道对称 + 接活死分支
- 新增 `pay full [mm|idx]`（别名 `invest full`）——「全额投资」不再只有鼠标；
- 工具栏新增 **配置** 按钮（等同 `config`）；理财条「全额投资」按钮改为回灌 `runCommand("pay full …")`，与命令行**同一条通道**；
- `list` 每行新增 **✎ 编辑** → `openEdit()` 进入 `modalMode="edit"`，提交拼成 `update <id> …` 回灌命令行，
  接活原来不可达的弹窗 edit 分支；编辑态隐藏选项卡，失效行（undo/del 之后）不可编辑。

### 2. H4（来自 v0.09-rev.2）：唯一提交点
- 新增 `refreshAll()` = `refreshHeader()` + `refreshHistoryUI()` + `refreshCatlist()`；
- 新增 `commit()` = `save()` + `refreshAll()`，命令出口统一 `commitIfDirty()`；
- 命令函数只改 `state`；`investAmount()` 不再自己落盘；
- `save()` 25 → 2 处（`loadState` 启动 + `commit`），`refreshHeader()` 23 → 1 处（`refreshAll`）。

## 二、合并时发现并修掉的问题

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 两条修订都改了 `doInvestFull`：rev.1 抽出了 `investFullRun()`（不自带 `mutate`），rev.2 把 `commitIfDirty()` 放在执行路径里。若照搬，会让"执行体自己提交"，与 H4 的"出口唯一提交"打架；在程序化入口 `doInvestFull()` 上还会出现**改了数据却不落盘**（`mutate` 尚未置位 `pendingCommit`，`commitIfDirty()` 变成空转） | 把 `commitIfDirty()` 从 `investFullRun()` 移到 `doInvestFull()`（`mutate` 之后）；命令路径仍由 `runCommand` 出口提交 —— 既保持"一次全额投资只压一步撤销"，又保住唯一提交点 |
| 2 | `renderRecordRow()` 被两条修订同时改：H5 加 **✎ 编辑** 按钮、H4 改投资按钮的提交方式 | 合并为"两个按钮都在、投资按钮走出口 `commitIfDirty()`"；`test6` 与 `test2` 双重覆盖 |
| 3 | `doPay` 同时含 H5 的 `full` 分支与 H4 的"删 `save()`/`refreshHeader()`" | 合并后 `doPay` 只改 `state`，`full` 分支转 `doPayFull()` |
| 4 | rev.2 的 3 组 H4 变异只写在文档里、没进脚本，护栏无法自动复现 | 把 `m_commit_exit` / `m_commit_refresh` / `m_commit_save` 正式加入 `tests/mutate-amort.mjs`（脚本 15 → 18 组） |
| 5 | 上面第 1 条的"程序化入口不落盘"是测试盲区（原 `test6` 只查 state） | 新增断言 **H5.43**（`doInvestFull` 之后结果已进 `localStorage`）与变异 `m_investfull_commit`（脚本 18 → 19 组），把该路径钉死 |
| 6 | 文档里测试/变异数字在两条线上各说各的（455 / 497、16 / 22） | 统一为 v0.0.9 实测值：**498 条断言 / 19 组脚本变异（实测 26 组）**，并同步 README / ARCHITECTURE-REVIEW / HANDOVER / tests/README |
