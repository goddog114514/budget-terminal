> **命令、参数、数据结构、备份格式、派生口径一个字都没改**：改的只是"谁负责保存和刷新界面"。

- **发布日期**：2026-10-15

- **升级方式**：用新的 `index.html` 覆盖旧文件即可；数据与旧备份**完全兼容**（v0.0.1 起的备份都能正确导入，**无需迁移**）

---

## 一句话

以前**每个命令各写一遍** `save()` 与 `refreshHeader()`（全文件 25 处 / 23 处，散落在 20+ 个函数里）——
新增命令时漏掉任何一个，就会出现"数据改了但界面没刷新"或"刷新后数据丢了"。
现在命令**只改 `state`**，落盘与刷新在**唯一出口** `commit()` 里统一完成，这类缺陷从结构上被消除。

---

## 一、问题（H4 / F10）

| 场景 | 老行为 | 期望 |
| --- | --- | --- |
| 新增一条命令，忘了 `save()` | 数据只在内存里，刷新页面丢失 | 出口自动落盘 |
| 新增一条命令，忘了 `refreshHeader()` | 顶栏仍是旧数字（v0.0.4 的"改设置顶栏不刷新"就是它） | 出口自动刷新 |
| 同一个"提交"动作 | 三套写法并存：命令靠 `mutate` 包一层 / UI 处理函数再包一层 / 领域函数内部直接 `save()` | 一个出口 |

## 二、原因

"改数据 → 落盘 → 刷新"这条链路没有单一负责人：`save()` 25 处、`refreshHeader()` 23 处，
每新增一个改数据的入口就多一处"需要记得调两个函数"的地方 —— 迟早会漏。

## 三、解决

- 新增 `refreshAll()` = `refreshHeader()` + `refreshHistoryUI()` + `refreshCatlist()`；
- 新增**唯一提交点** `commit()` = `save()` + `refreshAll()`，以及 `commitIfDirty()`；
- `runCommand()` 出口统一提交；是否"需要提交"由 `mutate()` 在快照确实变化时置位 `pendingCommit` 决定，
  因此只读命令（`list`/`summary`/`help`/`config`…）不会白写盘、也不会白刷新；
- 命令函数（`doSet`/`doBudget`/`doAdd`/`doAmort`/`doDelete`/`doUpdate`/`doPay`…）只改 `state`，
  删掉各自的 `save()` / `refreshHeader()`；`investAmount()` 不再自己落盘；
- 非命令入口（列表行「标记已投资」、`doInvestFull()`、`restoreFromText()`、`applyState()`/撤销重做）
  各自在出口调用 `commit` / `commitIfDirty`；
- `commit()` 含 `refreshCatlist()`：**导入备份后自定义类别立即回到表单下拉**（H3 的导入路径顺带受益）。

**效果**：`save()` 25 → **2** 处（`loadState` 启动 + `commit` 出口），`refreshHeader()` 23 → **1** 处（`refreshAll`）。

## 四、兼容性（**不需要迁移**）

- **未改动**：`LS_KEY`、备份 `app`/`version` 头、字段名、`amount` 语义、`r2`/`r6`、13:2 拆池、
  `COMMANDS` 命令清单（本版**不新增命令**）、响应式 CSS 契约。
- 老备份与 `localStorage` 直接可用，导入结果与升级前逐字段一致。
