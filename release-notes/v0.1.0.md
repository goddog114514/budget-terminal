# BUDGET::TERM v0.1.0 发布说明

> **三个页面（主页 / 钱包 / 设置）+ 多钱包 + 「记一笔」选钱包付款。**
> 顶部标签（`Alt+1/2/3`）切换：**主页就是原来的终端界面**，钱包页管付款账户，设置页把配置摊开在页面上直接改。
> 钱包余额**手动维护**（存入 / 取出），支出时选一个钱包付款；余额按**总价**、**截至今天**扣减，
> **不参与预算的发放 / 占用 / 结转** —— 钱包与预算只并排对照，两边各自计算。
> 数据层：`LS_KEY`、备份头（`app/version`）、`amount` 语义、精度、13:2 投资拆分、周期 / 结转 / 类别余额口径**全部未改**；
> 新增 `state.wallets` / `state.wops` 与记录字段 `wallet`，旧数据与旧备份零迁移。

- **升级方式**：用新的 `index.html` 覆盖旧文件即可；v0.0.1 起的备份都能导入（没有钱包字段 → 自动建「默认钱包」，旧记录标为"未指定钱包"）

## 一、三个页面

| 页面 | 内容 | 快捷键 |
| --- | --- | --- |
| **主页** | 终端输出、命令行、工具栏、下拉、理财条 —— 与 v0.0.15 一致（变化：**「配置 ▾」「地点 ▾」两个下拉随本版移除**，配置全部在设置页） | `Alt+1` |
| **钱包** | 概览条（余额合计 ↔ 预算可用余额）、本期各钱包支出占比堆叠条、每钱包一张卡（存入 / 取出 / 设为默认 / 重命名 / 删除）、最近流水 | `Alt+2` |
| **设置** | 周期预算、周期持续时间、投资比例、类别余额、地点与地图 Key、预警与收益参数 —— **页内直接改** | `Alt+3` |

- **同一套命令**：两页上的每个动作都拼命令字符串回灌 `runCommand`（钱包卡「存入」= `wallet in "微信" 500`、

- **终端回显**：命令输出永远进主页终端；在钱包 / 设置页执行时，本次新增的输出行镜像到页底回显条（最多 30 行）；
- **浮层互斥**：换页前 `closeAllOverlays()`，不会出现"下拉没关就切页"；
- 收起主页用的是 `.page-hide{display:none !important}`（`header` 自带 `display:flex`，会盖掉原生 `hidden`）。

## 二、钱包（付款账户）

| 能力 | 说明 |
| --- | --- |
| 新建 / 删除 | `wallet add <名称> [初始金额] [备注..]`；`wallet del <钱包>`（流水一并删除、由它支付的支出改记默认钱包、**最后一个不能删**） |
| 手动维护余额 | `wallet in` 存入 / `wallet out` 取出（可带 `@日期`，晚于今天的流水到那天才计入） |
| 默认钱包 | `wallet use <钱包>`；记支出不写 `$钱包` 就用它 |
| 重命名 | `wallet name <钱包> <新名称>`：记录存的是钱包 id，已有记录自动跟着改 |
| 改付款钱包 | `wallet mv <记录id> <钱包>`；或在编辑弹窗里换 |
| 流水 | `wallet log [钱包] [N]`：存入 / 取出 / 支出扣款（按总价），日期倒序 |
| 总览 | `wallet`：每个钱包余额 / 本期支出 / 笔数 + 合计 + **与预算可用余额的对照** |

三条口径（严格分开）：

| 数字 | 算法 |
| --- | --- |
| 钱包余额 | **存入 − 取出 − 已付支出**（支出按 `recTotal()` **总价**，只算**截至今天**） |
| 本期支出（每个钱包） | **消费口径**（与 `budget` 的「本期消费」同一把尺子：分摊按落在本期的天数计）→ 各钱包之和 = 本期消费 |
| 与预算对照 | 钱包余额合计 ↔ `可用余额(含结转)`：只展示多 / 少多少，两边互不影响 |

余额是**派生值**（删记录、改金额、`wallet mv`、`undo` 之后都自动重算），没有缓存副本。

## 三、「记一笔」选钱包付款

- 三个选项卡（单笔 / 分摊 / 经常性）各有一个**支付钱包**下拉，默认选中默认钱包；
- 选默认钱包 → 回灌的命令与 v0.1.0 之前**一字不差**（不带参数），老脚本 / 老习惯不受影响；
- 选其它钱包 → 命令带 `$"微信"`（位置无关参数，与 `#地点` 同一套解析；名字带空格写 `$"招商 卡"`）；
- 分摊成本 / 经常性支出（分摊）对钱包按**总价一次扣款**；不分摊的经常性支出每笔各扣一次；
- 编辑记录时下拉预填原钱包；旧记录（钱包功能上线前）显示默认钱包、不改就不动它。

```text
wallet add 微信 500 零钱          # 新建钱包 + 初始流水
wallet in 微信 1000 工资          # 存入
add 50 餐饮 午餐 $微信             # 这笔由微信付款
amort 3000 365 房租 $现金          # 分摊成本: 现金一次性扣 3000(不是每天 8.22)
wallet mv 3 现金                  # #3 改由现金支付
wallet                            # 总览 + 与预算对照
```

## 四、设置页（页内直接改，不写第二套表单）

`SETTING_CARDS` 六张卡：

1. **周期预算**（+ 每日可用余额）—— 回灌 `config set budget` / `set daily`
2. **周期持续时间**（按月 / 自定义日期 + 起止日 + 实时天数）—— 回灌 `config set period …`；另加「按月模式的月起始日」一行 → `config set monthstart`
3. **投资比例** —— 回灌 `config set invest`
4. **类别余额**（信封）—— 回灌 `set category …`
5. **地点与地图 Key** —— 回灌 `config set geo` / `config set geokey` / `place`
6. **预警与收益参数**（阈值 / 周起始日 / 年化）—— 回灌 `set alert` / `set weekstart` / `set rate`

- 前五张卡**直接挂载既有弹窗面板**：同一个 DOM 节点在「主页弹窗 ↔ 设置页卡片」之间搬动，离开设置页再搬回各自的遮罩层。
  因此没有第二套表单、没有第二套校验；主页工具栏的「配置 ▾」已移除（见下方「配置入口只剩设置页」）；
- 卡片标题旁一行**实时摘要**（默认/当期预算、本期区间与天数、消费投资比例、已配置类别、地点与 Key、阈值与年化）；
- 表单**只在数据确实变化后**才回填成已保存值 —— 校验失败的命令不会冲掉你正在输入的内容；
- 设置页里的「取消 / 关闭」按钮由 `data-close` 标记 + CSS 隐藏（页内表单没有"取消"语义）。

## 六、月起始日收进 `config`

```text
config set monthstart 15      # 每月 15 日 ~ 下月 14 日为一期
config set monthstart natural # 自然月(等价于 1)
```

与旧写法 `set monthstart` 共用同一个校验入口 `monthStartSet()`；现在会拒绝小数
（以前 `set monthstart 15.5` 能写进设置，重启被归一化回 1）。

## 七、同版修复 · 日期校验（数据丢失）

`@日期` 以前只校验"长得像 `YYYY-MM-DD`"：`add 50 餐饮 @2027-13-40` 或 `@2027-02-30` 能落库，
而**下次加载**时 `normalizeRecords → repairDate` 认定它非法，那条记录被当成"损坏"**静默丢掉**（记账变少）。

现在 `cleanDateStr()` 走 `normDateText()` 单一入口：不存在的日期**当场拒绝**（`add / amort / recur / update / wallet` 全部生效），
并顺带容忍 `2027/8/5`、`2027年8月5日`、`20270805` 等写法（与「手动输日期」弹窗同一套解析）。

| 项 | 结论 |

## 十、已知边界

- 钱包**不校验余额是否足够**：允许花成负数（标红提示），因为真正的余额由用户手动维护，应用无权拒绝记账；
- 「钱包余额 ↔ 预算可用余额」只是并排对照，**不做自动对账**（两边口径不同，见第二节表格）；
- 备份里若出现重名钱包，导入时**只保留第一个**（`$钱包` 按名字寻址，重名会让"付的是哪个"有歧义），其余计入丢弃计数；
- 设置页的「预警与收益参数」与「月起始日」是本页专有表单（命令行同样可用），改动仍走命令、一步撤销。
